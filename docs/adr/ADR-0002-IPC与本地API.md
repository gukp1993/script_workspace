# ADR-0002：IPC 与本地 API——MVP 仅回环绑定 + 随机会话令牌 + Origin 校验

## 背景

ADR-0001 将平台划分为桌面壳、运行时引擎与输入代理三个进程，需要一套本地 IPC。同时控制面会暴露本地 API 供 UI 使用。若不设防：

- 本机任意进程可探测并调用 API，伪造输入意图或读取项目数据；
- 浏览器中恶意页面可借用户会话发起跨站请求（本地 API 劫持，见威胁模型 TM-04）；
- 高帧率原始画面若经 JSON/Base64 传输，会拖垮事件通道并放大泄露面。

## 决策

### MVP 方案（M1 落地）

- 仅绑定 `127.0.0.1`，不监听任何外部地址；
- 每次启动生成随机会话令牌；无令牌请求被拒绝（CTL-001）；
- 禁止任意 Origin：拒绝未知 Origin、Host 和不兼容协议版本（CTL-002）；
- WebSocket 只传事件与低帧率调试缩略图；
- 原始高帧率画面留在运行时进程，不通过 JSON/Base64 传输（CTL-007）。

### 产品化路线（评估后替换或叠加，不构成 M0-M3 承诺）

- Windows Named Pipe；
- Tauri `invoke` + Python sidecar；
- 共享内存传递预览帧；
- 明确的消息版本和向后兼容策略（由 TST-004 契约测试守护）。

## 理由

- 回环绑定 + 启动期随机令牌把"调用者必须是本机且持有本会话凭据"变为机器可校验条件，直接对应质量闸门"无令牌请求被拒绝"（SEC-001 用例）；
- Origin/Host 校验阻断浏览器发起的跨站伪造请求（SEC-002 用例：恶意 Origin/Host 请求被拒绝）；
- 事件与缩略图走 WebSocket、原始帧留在运行时进程，兼顾可观察性与性能，符合质量门槛"预览卡顿不影响 Broker 和急停"；
- Named Pipe/Tauri invoke/共享内存是 Windows 产品化阶段的更强边界，但 MVP 阶段收益不足以抵偿迁移成本，列为路线而非承诺。

## 后果与影响

- CTL-001/002 成为 M1 P0 安全任务；SEC-003 要求完成端口绑定、CSRF/Origin、令牌、错误信息和速率限制的攻击面检查；
- 契约测试（TST-004）必须固定消息样例与版本矩阵，消息版本不兼容时明确失败；
- 切换到 Named Pipe 或 Tauri invoke 时须新增 ADR，不得静默更换；
- 令牌生命周期与桌面壳进程绑定（UI-001），壳退出后令牌失效。
