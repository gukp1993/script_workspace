# ADR-0005：运行轨迹与回放——RunTrace 事件链、双模式回放与决策确定性

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |

| 里程碑 | M0 定义格式、M1-M2 落地 |

| 来源 | 《GitHub 调研与安全架构》§6.2 第 10 项、§7.4；《任务与测试验收方案》§1.1 不变量 6 |

## 背景

"昨天能跑、今天改了一个模板就不行，但无法复现"是视觉自动化项目最常见的失效模式。没有运行轨迹，安全事件（策略拒绝、急停、失焦）也无法审计。任务文档 §1.1 不变量 6 冻结：

> 每次运行必须生成可追溯轨迹；同版本、同轨迹、同随机种子必须得到同一决策结果。

## 决策

### 1. RunTrace 事件链

一次运行应能导出：

```text
时间戳 + 帧引用 + 感知结果 + 状态 + 意图 + 策略结果
```

RunTrace 覆盖帧引用、感知、状态、意图、策略、执行、异常和版本哈希（TRC-001，M0 冻结格式）。审计与不可抵赖运行记录至少包括（架构文档 §6.2 第 10 项）：

- 脚本版本、资产哈希、模型版本；
- 目标窗口和标定配置；
- 感知快照；
- 状态迁移；
- 动作意图；
- 策略拒绝；
- 急停、失焦和异常。

按会话形成哈希链，方便判断日志是否被修改。

### 2. 双模式回放

- **固定感知回放**：跳过视觉，直接重放事实（PerceptionSnapshot），测试状态机（TRC-005）；
- **原始帧回放**：重新执行视觉管线，检查算法或阈值变更造成的差异（TRC-006）。

差异引擎按首个分歧点、受影响对象和严重度展示差异（TRC-007）。

### 3. 确定性要求

- 同版本、同轨迹、同随机种子必须得到同一决策结果；FSM-009 提供确定性随机源与决策哈希，同版本、同轨迹、同种子输出相同状态和意图哈希；
- 状态机使用可注入时钟、定时器与超时（FSM-005），所有定时行为可回放；
- 量化门槛：同版本、同轨迹、同种子连续运行 100 次，状态/意图哈希一致率 100%（任务文档 §7.2、AC-P0-08）；
- 跨模块时间同步使用单调时钟，可处理系统时钟跳变（TRC-004、CAP-004）。

### 4. 帧存储与隐私

- 帧内容寻址存储与索引，重复帧去重；引用不存在时明确报错；原始帧可按策略关闭（TRC-003）；
- 轨迹导出默认脱敏，去除账号名、路径、窗口标题敏感段和非必要原图（TRC-009）。

## 理由

- 轨迹是回放、差异分析、审计和"变更影响分析"（模板 → 检测器 → 感知字段 → 状态迁移 → 测试 → 项目）的共同底座；
- 双模式回放分离了两类回归来源：状态机逻辑回归用固定感知回放验证，视觉回归用原始帧回放发现（AC-P0-09）；
- 确定性哈希把"可复现"从口头承诺变成每次 CI 可断言的指标。

## 后果与影响

- M0 必须冻结 RunTrace 格式（TRC-001），格式变更走 ADR 与迁移；
- 轨迹写入需追加写、批量刷新与崩溃容错：崩溃前已确认事件可读取，尾部损坏可检测和截断（TRC-002）；
- 原始帧存储带来磁盘占用，需保留策略与安全清理（TRC-010）；
- 发布闸门要求轨迹能指出实际使用的脚本、资产、策略和运行时版本（一票否决项）。
