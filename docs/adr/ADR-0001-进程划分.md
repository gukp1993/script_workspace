# ADR-0001：进程划分——桌面壳、运行时引擎与输入代理三进程

| 项 | 内容 |

| 关联任务 ID | GOV-002（主责）、ENG-001、UI-001、CTL-001、CTL-005、CTL-006、INP-003、INP-004、INP-006、INP-007 |

## 背景

本平台会向前台窗口发送真实键鼠输入。若 UI、决策逻辑与输入执行处于同一进程，则：

1. 任何一层崩溃都可能让按键停留在"按下"状态，无法保证"崩溃时不能留下按键按下状态"；
2. UI 主线程卡死时可能没有独立路径停止输入（验收用例 SAFE-009、AC-P0-04 明确要求 UI 卡死时急停仍生效）；
3. 脚本与决策层可以绕过策略直接调用系统输入，违反架构不变量 1/2；
4. 展示层一旦拥有输入能力，攻击面与测试面都会失控。

架构文档 §3.2 已给出三进程建议，本 ADR 将其冻结为强制边界。

## 决策

平台按三个进程划分。M0-M1 期间进程 C 可以先与进程 B 合并实现，但代码边界必须按进程隔离，输入代理随后必须拆分为独立进程。

### 进程 A：桌面壳与 UI（`apps/desktop_shell` + `apps/workbench_ui`）

- 展示项目、图像、状态图、运行日志；
- 不直接发送输入；
- 崩溃时不能留下按键按下状态；
- 默认普通用户权限运行。

### 进程 B：运行时引擎（`services/runtime_engine` + `services/control_plane`）

- 截屏、视觉、状态机、测试、回放；
- 产生抽象的 `InputIntent`；
- 不直接信任脚本提供的可执行代码；
- 单会话、单目标窗口。

### 进程 C：输入代理（`services/input_broker`）

- 只接受有限动作：按下、释放、点击、移动、滚轮；
- 每批动作都带目标窗口标识、过期时间、会话 ID；
- 执行前再次核验前台窗口；
- 失焦、超时、急停、父进程退出时释放所有按键；
- 不提供读内存、注入、驱动、封包等接口。

## 理由

- 输入代理是唯一拥有 OS 输入能力的进程，使架构不变量 2（"所有真实输入必须经过 `Policy Guard` 和 `Input Broker`"）在进程边界即可强制执行，而不依赖约定；
- UI 崩溃或卡死不影响急停与按键释放（AC-P0-04、SAFE-009）；
- 运行时/控制面崩溃时，输入代理可通过看门狗感知父进程退出并释放全部按键（INP-007、SAFE-010、AC-P0-05）；
- 单会话、单目标窗口约束（CTL-006）集中在运行时引擎实现，避免多会话争抢同一输入代理。

## 后果与影响

- 引入进程间通信与生命周期管理成本，IPC 安全方案见 ADR-0002；
- UI-001 要求桌面壳启动/关闭能正确管理后端子进程，异常退出触发 Broker 清理；
- INP-007（父进程/代理看门狗与崩溃清理）成为 M1 必交付项；
- 排障必须跨进程关联，依赖 ENG-005 的结构化日志与 `correlation_id`；
- 契约测试（TST-004）需要覆盖跨进程消息版本兼容性。
