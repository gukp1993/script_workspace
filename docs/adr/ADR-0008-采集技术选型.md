## 背景

采集是感知闭环的第一环，需要高帧率、时间戳稳定、可诊断，并在采集后端故障时保持安全（不使用旧帧继续决策）。Windows 下可选 DXcam（封装 WGC/DXGI 路径）与 python-mss 等。

## 决策

1. **主采集适配器：DXcam（Windows Graphics Capture / DXGI Desktop Duplication 路径）**。作为 Windows 主采集适配器；封装统一接口，不让业务直接依赖具体后端（CAP-002）。
2. **兼容回退：python-mss**。作为兼容回退和测试基线，不作为唯一高性能路径（CAP-003）；接口与主适配器一致，可手动或自动降级。
3. **统一 Capture API**：统一像素格式、尺寸、时间戳、目标信息、ROI 和帧序号（CAP-001）；异常返回明确状态而不是旧帧。
4. **故障安全**：黑帧、尺寸异常、设备丢失时停止输入并可安全切换适配器（CAP-007）；回退成功也需要重新确认目标/标定（AC-P0-13）。
5. **附带口径（沿用架构文档 §0）**：OpenCV 为视觉第一优先；OCR 仅在裁剪区域按事件触发；YOLO 延后到有数据集、基线指标和明确必要性之后。

## 理由

- DXcam 提供 Windows 高帧率采集，满足质量门槛"1080p 基准场景持续 ≥ 30 FPS；采集 p95 延迟 ≤ 50 ms"；
- python-mss 简单、与 NumPy/OpenCV 衔接容易，作为回退与 CI 中的确定性测试基线；
- 统一接口 + 明确错误状态使"采集黑帧安全降级"成为可测试路径，而不是静默使用旧帧；
- 封装层隔离后端差异，后续更换采集后端不需要改动感知与状态机。

## 后果与影响

- 采集目标必须在会话启动时绑定（依赖 TGT-009 单会话目标锁）；
- 帧环形缓冲与单调时钟（CAP-004）是时间戳稳定性的前提，供 TRC-004 跨模块时间同步使用；
- 慢检测器不能拖死采集：背压、丢帧和消费者隔离（CAP-006）需要计数与告警；
- 适配器切换属于影响输入安全的变更，必须记录事件并重新确认目标（INP-005 复核链路）。
