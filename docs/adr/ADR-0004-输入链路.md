# ADR-0004：输入链路——Decision Engine → InputIntent → Policy Guard → Input Broker → Win32 SendInput

## 背景

PyAutoGUI / PyDirectInput 适合原型，不适合作为平台边界：它们不提供强类型输入意图、窗口校验、按键状态跟踪、焦点丢失保护和按键释放逻辑，无法在 Dry Run 中完全替换真实输入。任务文档 §1.1 不变量 1-4 冻结了输入侧的四条硬约束：

1. UI、脚本和检测器均不得直接调用系统输入；只能产生 `InputIntent`；
2. 所有真实输入必须经过 `Policy Guard` 和 `Input Broker`；
3. 每批输入执行前重新核验 HWND、PID、目标实例、前台状态、会话和 TTL；
4. 失焦、急停、父进程退出、锁屏、会话切换或状态不确定时，先停止输入并释放全部按键。

## 决策

推荐输入栈固定为以下分层，任何真实输入都必须走完整链路：

```text
Decision Engine
    ↓ 产生 InputIntent，不直接按键
Policy Guard
    ↓ 检查目标、焦点、预算、运行模式
Input Broker
    ↓ 跟踪按下/释放、批次、超时、取消
Win32 SendInput Adapter
    ↓
Windows
```

配套决策：

1. **InputIntent 是唯一通道**：抽象动作意图不直接绑定底层库；每批含 session、target、TTL、cause（INP-001）。
2. **每批动作前核验前台窗口**：不是启动时检查一次，而是在每个输入批次前检查当前前台 HWND、进程 ID、目标实例、会话是否仍有效、意图是否过期（INP-005、TGT-003、TGT-009）；不一致或过期时真实输入为 0。
3. **失焦即停并释放按键**：失焦后不尝试自动抢回焦点；立即取消队列、释放所有已按下键，并进入需要人工恢复的状态（INP-008；锁屏、用户切换、RDP 同样处理）。
4. **全局急停**：独立于 UI 线程；即使预览卡死仍能触发；首次触发立即停止输入，第二步再做清理；可配置双热键，但必须有不可取消的默认组合（INP-006）。
5. **按键状态账本与幂等释放**：任何停止路径都能释放所有已按下键，重复释放无副作用（INP-004）；父进程/代理看门狗在心跳中断后自动释放键并拒绝新意图（INP-007）。
6. **适配层边界**：Win32 SendInput 适配器支持扫描码、鼠标、批次结果和错误码，不提供注入、驱动或后台输入（INP-003）；PyAutoGUI / PyDirectInput 仅做原型或兼容适配，不作为核心引擎。
7. **FakeInputSink 用于测试与 Dry Run**：完整记录将执行动作，可注入失败和延迟，绝不调用系统输入（INP-002）。

## 理由

- 分层使"将要执行什么"可以被测试（Safe 用例 SAFE-001~022）并在 Dry Run 中完全替换真实输入（AC-P0-02）；
- 二次核验把"错误目标窗口零输入"（AC-P0-01）从启动时检查升级为每批检查，覆盖 HWND 复用、同名窗口、目标重启等时序问题；
- 按键状态账本 + 幂等释放保证急停、失焦、崩溃等所有异常路径收敛到"无卡键"这一可测试结论。

## 后果与影响

- 状态机运行时只产生意图，不直接调用输入 API（FSM-004）；取消后不产生新意图（FSM-006）；
- 策略默认拒绝，每次拒绝返回机器可读原因（POL-001）；模式机 Observe/Shadow/DryRun/RealInput 由 POL-002 实现，Shadow/DryRun 不调用 OS 输入；
- 急停延迟有量化门槛：从热键事件到 Broker 禁止新输入并开始释放 p95 ≤ 150 ms，全量释放 p95 ≤ 300 ms（任务文档 §7.2）；
- INP-003/004/006/007 为 M1 Windows 后端关键路径，安排需并行保护。
