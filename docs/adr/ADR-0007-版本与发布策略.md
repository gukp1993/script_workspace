# ADR-0007：版本与发布策略——SemVer、Schema 版本冻结、整体回滚与候选版质量闸门

## 背景

一次"可发布版本"不只是脚本文件：脚本、视觉资产、阈值、标定、策略、Schema 与运行时必须作为整体冻结，否则回滚会留下半新半旧的状态，运行记录也无法回答"当时到底运行了什么"。GOV-005 要求定义 SemVer、Schema 版本、兼容范围、分支保护、候选版和回滚策略。

## 决策

### 1. 版本规则

- 平台运行时与项目包采用语义化版本（SemVer）；
- DSL/项目 Schema 版本独立演进、可迁移、可锁版本（DOM-004：向前迁移、预检、备份和失败回滚，迁移结果可重复）；
- Schema 版本在里程碑冻结期不接受破坏性变更；变更触发影响分析（任务文档 §16.1）。

### 2. 发布冻结清单

一次可发布版本必须冻结（架构文档 §10.1）：

- DSL schema 版本；
- 状态机；
- 视觉资产和哈希；
- 阈值；
- 标定配置；
- OCR/模型版本；
- 策略配置；
- 运行时兼容范围；
- 测试结果。

发布后内容不可原地修改，任何变化产生新版本（VER-002）。

### 3. 发布流程

```text
草稿
  → 静态检查
  → 感知测试
  → 状态机测试
  → 轨迹回放
  → ArenaLab E2E
  → Shadow Mode
  → 人工审核
  → 签名发布
```

静态检查、感知、状态机、回放、E2E 未通过时不能发布（VER-005）。

### 4. 回滚

- 回滚必须整体回滚脚本包，不能只退 YAML 而保留新模板或新阈值（架构文档 §10.3）；
- 状态机、资产、阈值、标定和策略一起回滚；运行记录仍引用原版本（VER-008、AC-P0-12）；
- 升级前自动备份；迁移失败恢复到原可启动版本（VER-009、AC-P0-14）。

### 5. 分支保护与候选版闸门

- 主分支不允许带静态检查错误合并（ENG-004）；
- 候选版必须通过任务文档 §7 的发布质量闸门：§7.1 一票否决项任一出现即不得发布；§7.2 量化门槛（安全用例 100% 通过、急停/失焦延迟上限、确定性一致率 100%、覆盖率、视觉指标、性能、长稳、安装升级、缺陷分级）；
- 候选版归档产物与四方签字（产品 + TL + QA + 安全/发布）遵循任务文档 §15。

## 理由

- 冻结清单与内容寻址使运行轨迹能够指出实际使用的完整包，满足一票否决项"轨迹不能指出实际使用的脚本、资产、策略和运行时版本"的反向要求；
- 整体回滚消除"半迁移状态"这一类 P1 缺陷（回放不一致、资产版本错乱）；
- 质量闸门前置到候选版流程，避免把安全缺陷带进发布。

## 后果与影响

- 任何模板、阈值、策略或 Schema 变更都必须走影响分析与对应回归（任务文档 §16.1/§16.2），P0 安全回归与 ArenaLab 基本闭环始终执行；
- 发布包需要签名与校验（VER-006、REL-003）：未知签名默认不启用真实输入；
- 运行时兼容矩阵检查（VER-010）在不兼容时禁止运行并给出迁移建议；
- Schema/轨迹格式/IPC 变更属于跨版本决策，需新增 ADR。
