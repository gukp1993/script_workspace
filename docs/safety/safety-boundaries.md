## 1. 产品定位

> **可观察、可回放、可测试的 Windows 前台视觉自动化工作台。**

产品通过"屏幕采集 → 视觉感知 → 状态机决策 → 策略守卫 → 前台输入"形成闭环；所有真实输入都必须经过目标白名单、前台复核、模式、时限、配额、急停和审计控制。完整执行能力优先用于本地模拟器、离线软件、测试环境和明确允许自动化的目标；受保护在线游戏配置默认只开放观察、标注、回放与人工确认（Shadow）能力。

本产品不提供反作弊绕过、进程隐藏、驱动隐藏、内存读写、进程注入、封包操作或"拟人化逃避检测"方案；不把"在线游戏无人值守刷怪"作为验收目标，也不承诺账号安全。

## 2. 八条架构不变量（任务文档 §1.1 全文）

以下八条为不可变原则，任何设计与实现不得削弱：

1. UI、脚本和检测器均不得直接调用系统输入；只能产生 `InputIntent`。
2. 所有真实输入必须经过 `Policy Guard` 和 `Input Broker`。
3. 每批输入执行前重新核验 HWND、PID、目标实例、前台状态、会话和 TTL。
4. 失焦、急停、父进程退出、锁屏、会话切换或状态不确定时，先停止输入并释放全部按键。
5. 普通脚本使用声明式 YAML/JSON；M0-M3 禁止任意 Python、Shell、DLL 或系统命令执行。
6. 每次运行必须生成可追溯轨迹；同版本、同轨迹、同随机种子必须得到同一决策结果。
7. 真实输入优先用于 ArenaLab、本地、离线、自有或明确允许自动化的目标；受保护在线游戏配置默认只允许观察、标注、回放和 Shadow Mode。
8. 不实现进程隐藏、驱动隐藏、反作弊探测、内存读写、进程注入、封包截获/修改、硬件伪装、拟人化逃避检测、多账号集群或后台多开。

## 3. 明确不做清单（架构文档 §6.1）

平台代码、插件 API 和文档同时禁止以下八项：

1. 检测反作弊进程或驱动并据此改变行为；
2. 驱动隐藏、进程隐藏、窗口伪装、模块擦除；
3. 内存读取、内存写入、DLL 注入、远程线程；
4. 网络封包截获、修改、重放；
5. 硬件标识伪装；
6. 为逃避检测设计的“拟人化”轨迹、噪声和行为随机化；
7. 多账号、多开、集群调度和自动账号轮换；
8. 自动交易、拍卖、经济套利。

配套说明：随机化不进入脚本 DSL 默认概念（无通用 `humanize`、`random_path`、`random_click` 能力），只保留有边界的调度抖动，且仅用于避免多个内部任务争抢资源，不宣传为降低检测概率。受保护在线配置默认禁止无人值守能力：不允许定时自动开始、自动重连、自动关闭安全提示后继续、系统启动后自动运行、锁屏或远程会话切换后继续。

## 4. 风险分级表（架构文档 §6.3）

| 能力 | 风险 | 默认策略 |
|---|---|---|
| 截屏预览、画框、日志 | 低 | 允许 |
| 离线截图识别与回放 | 低 | 允许 |
| 本地测试程序真实输入 | 中 | 人工确认后允许 |
| 普通桌面应用前台自动化 | 中 | 目标白名单 + 限额 |
| 在线游戏观察/Shadow Mode | 中 | 允许，但不执行输入 |
| 在线游戏连续自动操作 | 高 | 默认禁用，不作为产品承诺能力 |
| 内存、注入、封包、驱动隐藏 | 不接受 | 架构级禁止 |

## 5. 首版质量闸门一票否决项摘要（任务文档 §7.1）

出现任意一项，候选版不得发布：

- 错误窗口、Shadow/Dry Run、失焦、锁屏、会话切换或过期意图仍产生真实输入；
- 急停或异常退出后存在未释放按键；
- 任意脚本/导入包可执行 Python、Shell、DLL、系统命令或绕过 Input Broker；
- 受保护在线目标能够通过修改项目文件启用 RealInput；
- P0/P1 缺陷未关闭且无正式豁免；
- 项目迁移或回滚可导致资产、状态机和策略版本不一致；
- 轨迹不能指出实际使用的脚本、资产、策略和运行时版本；
- 导入包存在路径穿越、Zip Slip 或覆盖项目根目录之外文件的能力。

## 6. 与代码的映射

上述边界不是文档约定，而是由代码层结构强制：

| 边界 | 代码落点 | 强制方式 |
|---|---|---|
| 不变量 1/2：意图唯一通道、策略前置 | `services/input_broker` | `InputIntent` 是唯一输入通道（INP-001），每批含 session、target、TTL、cause；Win32 SendInput 适配器（INP-003）不提供注入、驱动或后台输入 |
| 不变量 2/5：默认拒绝与硬锁 | `packages/policy_engine` | 策略求值器默认拒绝，每次拒绝返回机器可读原因（POL-001）；`protected_online` 目标的真实输入硬锁（POL-003）：被标记为 protected_online 的目标默认只能观察、标注、回放和 Shadow；模式机 Observe/Shadow/DryRun/RealInput 的 Shadow/DryRun 不调用 OS 输入（POL-002） |
| 不变量 4：按键释放 | `services/input_broker` | FakeInputSink（INP-002）完整记录将执行动作且绝不调用系统输入；按键状态账本与幂等释放（INP-004）、每批前目标复核（INP-005）、全局急停（INP-006）、父进程看门狗（INP-007） |
| 不变量 5：无任意代码入口 | `packages/policy_engine` + `packages/domain_model` | 能力清单与授权模型默认拒绝（DOM-005）；Schema 校验（DOM-002/003）在解析期拒绝越权配置；DSL、导入包和 UI 均无 exec/eval/shell 入口（SEC-001） |
| 不变量 7：受保护目标反例 | `examples/protected_online_demo` | 作为"必须被拒绝"的反例进入 Schema 校验与策略测试（SAFE-020：手改 real_input=true 由 Schema/Policy 双重拒绝）；UI 不提供绕过按钮（UI-016） |
| 不变量 6：可追溯 | `packages/trace_format` | RunTrace 版本化格式（TRC-001）覆盖帧引用、感知、状态、意图、策略、执行、异常和版本哈希 |

规则约定：任何 PR 若需要触碰上述包的安全路径（Policy Guard、Input Broker、Schema 校验），评审必须确认不变量未被削弱，见 `docs/governance/review-template.md`。
